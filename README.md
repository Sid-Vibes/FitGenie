# FitGenie

**AI-powered fitness tracking and personalized workout recommendation
system**

FitGenie is a fitness application that combines a Spring Boot backend
with a FastAPI-based machine learning service. It helps users manage
their fitness profiles, track activities and goals, view progress, and
receive workout recommendations generated by machine-learning models.

> **Project status:** The Spring Boot backend and FastAPI recommendation
> service are integrated. The recommendation generation, feedback, and
> history flows have been tested between the two services.

## Features

### User and authentication

-   User registration and login.
-   JWT-based authentication.
-   Refresh-token support.
-   User profile management.

### Fitness tracking

-   Record and manage fitness activities.
-   Retrieve activity history, including date-range filtering.
-   Calculate activity statistics such as workout count, exercise
    duration, calories burned, and distance.
-   Create and manage fitness goals.
-   View dashboard information.

### Machine-learning recommendations

-   Generate personalized workout recommendations through the ML
    service.
-   Use trained models to predict workout-related outputs.
-   Submit feedback on recommendations.
-   Retrieve recommendation history.

## Architecture

FitGenie is organized as two services:

1.  **Spring Boot backend** --- handles user authentication, profiles,
    activities, goals, dashboard data, and communication with the ML
    service.
2.  **FastAPI ML service** --- loads the trained machine-learning
    models, generates recommendations, and stores recommendation records
    and feedback in PostgreSQL.

High-level request flow:

``` text
Client
  |
  v
Spring Boot Backend
  |-- Authentication and user management
  |-- Activities, goals, and dashboard
  |
  |  HTTP request
  v
FastAPI ML Service
  |-- Feature preparation
  |-- Model inference
  |-- Recommendation persistence
  |
  v
PostgreSQL
```

The Spring Boot backend uses MySQL for its application data. The ML
service uses PostgreSQL for recommendation data.

## Machine-learning models

The ML service currently loads these serialized model files from
`ml-service/models/`:

  Model file                         Purpose
  ---------------------------------- ----------------------------------
  `activity_classifier_v2.joblib`    Activity-type classification
  `intensity_classifier_v2.joblib`   Workout-intensity classification
  `duration_regressor_v2.joblib`     Workout-duration prediction
  `distance_regressor_v2.joblib`     Distance prediction

The model files are tracked with **Git LFS**. Make sure Git LFS is
installed before cloning so the actual model files are downloaded rather
than only their pointer files.

The dataset currently included in the repository is
`ml-service/data/fitness_next_workout_v2.csv`.

## Getting started

### Prerequisites

Install the following before running the services:

-   Java and Maven (or use the included Maven wrapper).
-   Python 3.
-   MySQL.
-   PostgreSQL.
-   Git and Git LFS.

Use versions compatible with the dependencies in `backend/pom.xml` and
`ml-service/requirements.txt`.

### 1. Clone the repository

``` bash
git lfs install
git clone https://github.com/Sid-Vibes/FitGenie.git
cd FitGenie
```

### 2. Configure the Spring Boot backend

1.  Create the MySQL database for the backend.
2.  Open `backend/src/main/resources/application.properties`.
3.  Configure the database connection, JWT secret, and ML service
    connection settings.
4.  Supply credentials and secrets through environment variables or a
    local secret configuration. Do not commit real credentials or secret
    keys.

Run the backend from the repository root:

**Windows PowerShell**

``` powershell
cd backend
.\mvnw.cmd spring-boot:run
```

**macOS / Linux**

``` bash
cd backend
./mvnw spring-boot:run
```

### 3. Configure the ML service

1.  Create the PostgreSQL database used by the ML service.
2.  Configure the ML service's database connection using local
    environment settings.
3.  Confirm that the model files have been downloaded by Git LFS.
4.  Install the Python dependencies.

**Windows PowerShell**

``` powershell
cd ml-service
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

**macOS / Linux**

``` bash
cd ml-service
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Configure the database settings expected by
`ml-service/app/database/connection.py`. Do not commit database
passwords or other secrets.

### 4. Run the application

Start the ML service from the `ml-service` directory:

``` bash
uvicorn app.main:app --reload
```

Start the Spring Boot backend separately, using the commands in Step 2.

Make sure both services are running and that the backend's ML service
URL points to the FastAPI service address. Check the FastAPI interactive
API documentation at `/docs` on the ML service host.

> Exact ports, database names, credentials, and environment-variable
> names depend on your local configuration. Check the configuration
> files in each service and provide the required values locally before
> starting the application.

## API overview

The following integration routes are implemented in the Spring Boot
backend:

  -----------------------------------------------------------------------------------------------------------------------
  Method                  Route                                                                   Purpose
  ----------------------- ----------------------------------------------------------------------- -----------------------
  `POST`                  `/api/auth/register`                                                    Register a user

  `POST`                  `/api/auth/login`                                                       Authenticate a user

  `POST`                  `/api/ml/recommendations/generate`                                      Generate ML
                                                                                                  recommendations

  `PATCH`                 `/api/ml/recommendations/{recommendationId}/feedback?status=ACCEPTED`   Submit recommendation
                                                                                                  feedback

  `GET`                   `/api/ml/recommendations/history`                                       Retrieve recommendation
                                                                                                  history
  -----------------------------------------------------------------------------------------------------------------------

Protected routes require the authentication credentials expected by the
backend. The feedback route's `status` value should be one supported by
the application's recommendation-feedback implementation.

For the complete request and response schemas, refer to the DTOs and
controllers in `backend/src/main/java/com/fitnessApplication/`.

## Recommendation feedback flow

The recommendation workflow connects both services:

1.  The client requests recommendations from the Spring Boot backend.
2.  The backend sends the required data to the FastAPI ML service.
3.  The ML service prepares features and runs model inference.
4.  The generated recommendation is persisted by the ML service.
5.  The client can submit feedback, such as accepting a recommendation.
6.  The client can retrieve recommendation history and feedback status.

The recommendation generation, feedback update, and history retrieval
flows have been tested successfully during integration.

## Configuration and security

-   Keep database passwords, JWT secrets, API keys, and other
    credentials out of Git.
-   Use local environment variables or an untracked local configuration
    file for secrets.
-   Do not commit `.env` files or production credentials.
-   Use a strong, private JWT signing secret outside development.
-   Restrict database access and use appropriate credentials for each
    service.
